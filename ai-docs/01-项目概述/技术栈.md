### 1. TypeScript

**版本**: `^5.9.3`

**定位**: 项目的核心编程语言，提供类型安全保障

#### 配置文件 (tsconfig.json)

```json
{
  "compilerOptions": {
    // ========== 编译目标 ==========
    "target": "esnext", // 编译为 ESNext，使用最新特性
    "lib": ["es2023"], // 使用 ES2023 标准库

    // ========== 模块系统 ==========
    "moduleDetection": "force", // 强制模块检测
    "module": "preserve", // 保持 ES Module 格式
    "moduleResolution": "bundler", // Bundler 风格的模块解析

    // ========== 类型系统 ==========
    "resolveJsonModule": true, // 支持导入 JSON 模块
    "types": ["node"], // Node.js 类型定义
    "strict": true, // 启用所有严格类型检查
    "noUnusedLocals": true, // 禁止未使用的局部变量
    "declaration": true, // 生成 .d.ts 声明文件
    "emitDeclarationOnly": true, // 仅生成声明文件（不输出 JS）
    "esModuleInterop": true, // ES 模块互操作
    "isolatedModules": true, // 隔离模块编译（加速构建）
    "skipLibCheck": true // 跳过 node_modules 的类型检查

    // ========== 其他选项 ==========
    // "jsx": "preserve",         // JSX 支持（如需要）
    // "experimentalDecorators": true, // 装饰器支持（如需要）
  },
  "include": ["src"] // 包含源码目录
}
```

#### 关键特性应用

| 特性         | 配置项                        | 用途         | 示例                      |
| ------------ | ----------------------------- | ------------ | ------------------------- |
| **严格模式** | `strict: true`                | 类型安全     | 禁止隐式 any              |
| **装饰器**   | (可选)                        | 组件元数据   | `@Component`              |
| **泛型**     | 内置支持                      | 组件属性类型 | `TypeProps<T>`            |
| **模块解析** | `moduleResolution: "bundler"` | ESM 兼容     | 支持 package.json exports |

#### TypeScript 在项目中扮演角色

```typescript
// ✅ 类型安全的组件定义

    // 参数类型约束

### 2. TypeDom Framework

**版本**: `^0.5.0`

**定位**: 基于 TypeScript 的前端框架，提供类型安全的组件开发体验

#### 核心 API

```typescript
import {
  // ========== 基类 ==========
  TypeRoot, // 根组件（类似 React 的 Fragment）
  TypeSvgSvg, // SVG 根元素基类
  TypeElement, // 所有元素的基类
  SvgPath, // SVG 路径组件

  // ========== 类型定义 ==========
  SvgProps, // SVG 属性类型接口
  TypeProps, // 通用属性类型接口

  // ========== 工具函数 ==========
  addAttrObj, // 批量添加属性的工具函数
  addStyleObj, // 批量添加样式的工具函数
} from "@type-dom/framework";
```

#### 组件继承体系

```
TypeElement (抽象基类)
    │
    ├─ 属性：className, parent, childNodes
    ├─ 方法：addChild(), removeChild(), mount()
    │
    ↓
TypeSvg (SVG 抽象基类)
    │
    ├─ SVG 特定方法和属性
    │
    ↓
TypeSvgSvg (<svg> 元素基类)
    │
    ├─ 属性：viewBox, width, height
    ├─ 方法：resetSize()
    │
    ↓
具体 SVG 组件类
    │
    ├─ TdAddSvg (Common 分类)
    ├─ ElArrowDownSvg (Element Plus 分类)
    └─ FlAccessTimeFilledSvg (FluentUI 分类)
```

#### 完整示例代码

````typescript
import { SvgProps, SvgPath, TypeSvgSvg, addAttrObj } from "@type-dom/framework";

/**
 * 加号图标组件
 *
 * @example
 * ```typescript
 * const icon = new TdAddSvg({
 *   width: 32,
 *   height: 32,
 *   fill: '#ff0000'
 * });
 * ```
 */
export class TdAddSvg extends TypeSvgSvg {
  // 类型声明
  className: "TdAddSvg";
  override childNodes: SvgPath[];

  /**
   * 构造函数
   * @param params - SVG 属性参数
   */
  constructor(params: SvgProps = {}) {
    super(params);

    // 1. 设置类名（用于类型识别）
    this.className = "TdAddSvg";

    // 2. 添加基础属性
    addAttrObj(this, {
      name: "TdAddSvg", // 组件名称
      title: "Add Icon", // 标题（可选）
    });

    // 3. 设置 viewBox（统一 1024x1024 坐标系统）
    addAttrObj(this, {
      viewBox: "0 0 1024 1024",
    });

    // 4. 设置默认尺寸（24x24 像素）
    this.resetSize(24, 24);

    // 5. 初始化子节点数组
    this.childNodes = [];

    // 6. 创建 SVG 路径
    const path0 = new SvgPath({
      attrObj: {
        fill: "currentColor", // 使用 currentColor 便于主题切换
      },
    });

    // 7. 设置路径数据（SVG path d 属性）
    path0.setData("M512 42.666667c259.2 0 469.333333...");

    // 8. 将路径添加到 SVG
    this.addChild(path0);
  }
}
````

### 4. Tsdown

**版本**: 通过 `vite-plus/pack` 引入

**定位**: 现代化的打包工具，基于 Rollup，专注于 ESM 输出

#### 配置文件 (tsdown.config.ts)

```typescript
import { defineConfig } from "vite-plus/pack";

export default defineConfig({
  // ========== 类型声明生成 ==========
  dts: {
    tsgo: true, // 使用 TypeScript 官方编译器（非 swc）
  },

  // ========== 导出配置 ==========
  // 自动从 package.json 生成 exports 字段
  exports: true,

  // ========== 输出格式 ==========
  format: ["esm"], // 仅输出 ESM 格式

  // ========== 打包策略 ==========
  // CRITICAL: Unbundle 模式 - 保持源码目录结构
  unbundle: true, // 每个源文件独立输出

  // ========== 模块解析 ==========
  cwd: process.cwd(), // 设置项目根目录
});
```

#### 打包策略详解

```
✅ 保持源码目录结构
   src/lib/common/add.ts → dist/lib/common/add.mjs
   src/lib/common/close.ts → dist/lib/common/close.mjs

   优点:
   • 便于调试（源码映射清晰）
   • Tree-shaking 友好
   • 避免命名冲突

✅ 每个源文件独立输出
   不会将所有组件打包成一个大文件

   优点:
   • 按需加载
   • 减少初始加载时间
   • 更好的缓存策略

✅ 自动生成类型声明
   dist/lib/common/add.mjs
   dist/lib/common/add.d.ts  ← 配套的类型声明

   优点:
   • TypeScript 项目友好
   • IDE 智能提示
   • 类型安全检查
```

#### 构建流程

```
┌─────────────────────────────────────────────────────────┐
│                    Tsdown 构建流程                       │

│                                                         │

## 🔍 代码质量工具

### Oxlint

**配置文件**: `.oxlintrc.json`

**特点**:

- ✅ Rust 编写，极速 Lint（比 ESLint 快 50-100 倍）
- ✅ TypeScript 原生支持
- ✅ 类型感知 linting

**配置摘要**:

```json
{
  "rules": {
    // 代码质量规则
    "no-unused-vars": "error", // 禁止未使用变量
    "no-console": "warn", // 警告 console.log
    "prefer-const": "error", // 优先使用 const
    "no-var": "error", // 禁止 var

    // TypeScript 特定规则
    "@typescript-eslint/no-explicit-any": "warn",
    "@typescript-eslint/explicit-function-return-type": "off"
  }
}
```

### Git Staged Hooks

```typescript
// vite.config.ts
staged: {
  "*": "vp check --fix"
}
```

**作用**: Git commit 前自动检查和修复代码

**执行流程**:

```
git commit
    ↓
触发 staged hook
    ↓
vp check --fix
    ↓
自动修复可修复的问题
    ↓
报告不可修复的问题
    ↓
如果有错误，commit 失败
```

## 📚 技术选型理由

### Q1: 为什么选择 TypeScript？

**A**:

- ✅ **类型安全**: 编译时发现错误，减少运行时错误
- ✅ **IDE 支持**: 智能提示、自动补全、重构工具
- ✅ **可维护性**: 类型即文档，便于理解代码
- ✅ **生态系统**: 现代前端开发的标准

---

### Q2: 为什么选择 TypeDom？

**A**:

- ✅ **TypeScript 原生**: 深度集成，类型安全
- ✅ **轻量级**: 学习成本低，易于上手
- ✅ **灵活性**: 适合 SVG 封装场景
- ✅ **一致性**: 与项目"类型安全"目标一致

---

### Q3: 为什么使用 Vite Plus 而不是标准 Vite？

**A**:

- ✅ **更深的 TS 集成**: 无需额外配置
- ✅ **统一工具链**: vp 命令涵盖所有需求
- ✅ **tsdown 配置灵活**: 更适合库开发
- ✅ **类型感知 linting**: 更准确的代码检查

---

### Q4: 为什么保持 unbundle 模式？

**A**:

- ✅ **保持源码结构**: 便于调试和理解
- ✅ **tree-shaking 友好**: 每个文件独立
- ✅ **避免命名冲突**: 不会打包成大文件
- ✅ **按需加载**: 更好的性能
