# AI 优先宣言

**@type-dom/svgs 项目的 AI 协作开发理念**

**版本**: v0.4.0  
**最后更新**: 2026-03-19

---

## 🎯 我们的愿景

在@type-dom/svgs 项目中，我们相信**AI 与人类开发者的深度协作**将释放前所未有的创造力和生产力。

我们不是用 AI 替代人类，而是通过 AI **增强**人类开发者的能力。

---

## 💡 核心价值观

### 1. AI First, Human Centered

```
┌─────────────────────────────────────────────────────────┐
│              AI 优先，以人类为中心                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  AI 负责：                                                │
│  • 重复性劳动（模板代码、测试生成）                      │
│  • 快速原型（从 0 到 1 的草稿）                          │
│  • 质量检查（代码审查、规范验证）                        │
│  • 知识检索（文档查找、最佳实践）                        │
│                                                         │
│  人类负责：                                              │
│  • 创意构思（设计决策、架构规划）                        │
│  • 价值判断（优先级排序、权衡取舍）                      │
│  • 情感连接（用户体验、团队文化）                        │
│  • 创新突破（新技术探索、边界拓展）                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2. 文档即代码

- ✅ **同等重要**: 文档与代码享有同等地位
- ✅ **同步更新**: 代码变更必须伴随文档更新
- ✅ **版本控制**: 文档纳入 Git 版本管理
- ✅ **自动生成**: 能自动生成的绝不手动编写

### 3. 结构化知识

- ✅ **标准化格式**: 所有文档遵循统一结构
- ✅ **机器可读**: 便于 AI 理解和检索
- ✅ **语义标签**: 使用 AI 标签标注文档类型
- ✅ **关联网络**: 文档之间建立清晰链接

## 🚀 三大转变

### 转变 1: 从"手写代码"到"AI 生成 + 人工审核"

**传统模式**:

```
需求分析 → 设计方案 → 手写代码 → 手动测试 → 代码审查
耗时：4-8 小时
```

**AI 优先模式**:

```
需求分析 → AI 提示词 → 生成代码 → 人工审核 → 自动化测试
耗时：30-60 分钟
效率提升：85%+
```

**实践案例**:

```typescript
// ❌ 传统方式：手动编写每个 SVG 组件
export class AddSvg extends TypeSvgSvg {
  className: "AddSvg";
  constructor(params: SvgProps = {}) {
    super(params);
    // ... 50 行手动编写的代码
  }
}

// ✅ AI 优先方式：使用模板 + AI 生成
// 开发者提供：SVG 路径数据 + 组件名称
// AI 生成：完整组件代码 + 单元测试 + JSDoc 注释
```

### 转变 2: 从"事后文档"到"文档驱动开发"

**传统模式**:

```
编码完成 → 测试通过 → (有时间才写文档) → 文档过时 → 无人维护
```

**AI 优先模式**:

```
文档模板 → AI 生成草稿 → 人工完善 → 代码实现 → 自动同步更新
        ↓
   文档始终与代码保持一致
```

### 转变 3: 从"个人经验"到"集体智慧"

**传统模式**:

```
开发者 A 的经验 → 开发者 A 离职 → 经验丢失
开发者 B 踩过的坑 → 未记录 → 开发者 C 继续踩坑
```

**AI 优先模式**:

```
个人经验 → 文档化 → AI 学习 → 团队共享 → 新人快速上手
    ↓                                ↓
遇到问题            查询 AI 助手获得解答
```

## 📋 AI 协作原则

### 原则 1: 精准提问

```markdown
❌ 低效提问:
"帮我写个 SVG 组件"

✅ 高效提问:
【角色】TypeDom Framework 专家
【任务】创建 StarSvg 星星图标组件
【参考】@技术栈.md @编码规范.md
【要求】

- viewBox: 0 0 1024 1024
- 默认尺寸：24x24
- 支持自定义颜色
- 包含单元测试
  【路径数据】M512 42.666667...
```

### 原则 2: 上下文注入

```markdown
✅ 正确做法:

1. 引用相关文档（@文档名.md）
2. 提供项目背景信息
3. 说明技术栈和约束条件
4. 给出具体示例

❌ 错误做法:
直接提问，不提供任何上下文
```

### 原则 3: 迭代优化

```
第一轮：AI 生成基础代码
   ↓
第二轮：人工审查 + 提出改进意见
   ↓
第三轮：AI 根据反馈优化
   ↓
第四轮：自动化测试验证
   ↓
第五轮：人工最终审核 + 合并
```

### 原则 4: 质量保证

```
AI 生成 ≠ 直接使用

必须经过:
□ 人工审核（逻辑正确性）
□ 自动化测试（功能正确性）
□ 代码审查（规范符合性）
□ 性能测试（性能达标）
```

## 🚨 常见误区

### ❌ 误区 1: 完全依赖 AI

```
错误想法："AI 能生成所有代码，不需要人工审查"

正确认知："AI 是强大的助手，但需要人类把关"

风险：
- 生成错误难以发现
- 安全隐患被忽略
- 业务逻辑理解偏差
```

### ❌ 误区 2: 忽视文档质量

```
错误想法："有文档就行，质量不重要"

正确认知："低质量文档比没有文档更糟糕"

风险：
- 误导开发者和 AI
- 增加沟通成本
- 降低信任度
```

### ❌ 误区 3: 一次性完美主义

```
错误想法："第一次就要做到 100 分"

正确认知："快速迭代，持续改进"

建议：
- 先完成再完美
- 小步快跑
- 收集反馈持续优化
```
