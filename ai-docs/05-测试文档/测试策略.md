## 📊 测试类型定义

### 1. 单元测试 (Unit Tests)

**定义**: 测试单个 SVG 组件的功能和属性

**测试范围**:

- ✅ 组件实例化
- ✅ className 属性验证
- ✅ childNodes 类型检查
- ✅ viewBox 属性设置
- ✅ 默认尺寸验证
- ✅ 自定义 props 处理
- ✅ Path 数据正确性

**示例**:

```typescript
import { Td404Svg } from "../src/lib/common/404";

describe("Td404Svg", () => {
  it("should have correct className", () => {
    const svg404 = new Td404Svg();
    expect(svg404.className).toBe("Td404Svg");
  });

  it("should have viewBox attribute", () => {
    const svg404 = new Td404Svg();
    expect(svg404.getAttribute("viewBox")).toBe("0 0 128 128");
  });

  it("should accept custom props", () => {
    const svg404 = new Td404Svg({
      width: 32,
      height: 32,
      fill: "red",
    });
    expect(svg404).toBeDefined();
  });
});
```

### 2. 集成测试 (Integration Tests)

**定义**: 测试组件间的组合和交互

**测试范围**:

- ✅ 组件嵌套和组合
- ✅ Props 传递和继承
- ✅ 事件冒泡和处理
- ✅ 样式继承和覆盖
- ✅ 响应式更新联动

**示例**:

```typescript
import { TypeDiv } from "@type-dom/framework";
import { TdUserSvg, TdAddSvg } from "@type-dom/svgs/common";

describe("SVG Integration", () => {
  it("should render multiple SVGs in container", () => {
    const container = new TypeDiv();
    const userIcon = new TdUserSvg();
    const addIcon = new TdAddSvg();

    container.addChild(userIcon, addIcon);

    expect(container.childNodes.length).toBe(2);
  });

  it("should inherit styles from parent", () => {
    const container = new TypeDiv({
      style: { color: "blue" },
    });
    const icon = new TdUserSvg();
    container.addChild(icon);

    // Verify style inheritance
    expect(icon.props.fill).toBe("currentColor");
  });
});
```

### 3. E2E 测试 (End-to-End Tests)

**定义**: 在真实浏览器环境中测试完整功能

**测试范围**:

- ✅ SVG 渲染正确性
- ✅ 交互和动画效果
- ✅ 跨浏览器兼容性
- ✅ 性能表现 (FPS、内存)

**工具**: Playwright / Cypress (未来扩展)

## 🎯 覆盖率管理

### 覆盖率阈值配置

```typescript
// vitest.config.ts
export default {
  test: {
    coverage: {
      provider: "v8",
      reporter: ["text", "json", "html"],
      threshold: {
        lines: 90, // 行覆盖率 ≥ 90%
        functions: 95, // 函数覆盖率 ≥ 95%
        branches: 85, // 分支覆盖率 ≥ 85%
        statements: 90, // 语句覆盖率 ≥ 90%
      },
      include: ["src/lib/**/*.ts"],
      exclude: [
        "src/index.ts", // 导出文件
        "src/**/index.ts", // 分类导出
        "**/*.d.ts", // 类型声明
        "src/lib/fluentui/**", // 大型图标库 (可选排除)
      ],
    },
  },
};
```

## 🚀 CI/CD 集成

### GitHub Actions 配置

```yaml
# .github/workflows/test.yml
name: Test and Coverage

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: "20"

      - name: Install dependencies
        run: npm ci

      - name: Run type check
        run: npm run typecheck

      - name: Run tests with coverage
        run: npm test -- --coverage

      - name: Upload coverage reports
        uses: codecov/codecov-action@v3
        with:
          file: ./coverage/coverage-final.json
          fail_ci_if_error: false
```

## 📈 测试质量指标

### 测试健康度检查清单

```
□ 测试独立性：每个测试可独立运行
□ 测试可重复性：无随机失败
□ 测试速度：单个测试 < 100ms
□ 测试覆盖率：达到阈值要求
□ 测试可读性：清晰的命名和结构
□ 测试维护性：易于更新和扩展
```

### 常见问题和解决方案

| 问题            | 影响           | 解决方案       |
| --------------- | -------------- | -------------- |
| **测试耦合**    | 难以维护和调试 | 确保测试独立性 |
| **覆盖率虚高**  | 实际质量不高   | 增加断言深度   |
| **测试过慢**    | 开发效率低     | 优化测试用例   |
| **假阳性/阴性** | 信任度下降     | 修复测试逻辑   |
