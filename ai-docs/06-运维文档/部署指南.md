### 2.3 构建优化选项

**Unbundle 模式（保持源码结构）**

```typescript
// tsdown.config.ts
import { defineConfig } from "tsdown";

export default defineConfig({
  entry: ["src/index.ts"],
  format: ["esm"],
  outDir: "dist",
  dts: true,
  // 保持目录结构
  target: "esnext",
  minify: false, // 开发环境不压缩
  sourcemap: true, // 生成 source map
});
```

**生产优化模式**

```typescript
// tsdown.config.prod.ts
import { defineConfig } from "tsdown";

export default defineConfig({
  entry: ["src/index.ts"],
  format: ["esm"],
  outDir: "dist/prod",
  dts: true,
  target: "es2020",
  minify: "terser", // 压缩代码
  sourcemap: false, // 不生成 source map
  treeshake: true, // 启用 tree-shaking
});
```

## 📦 三、NPM 发布流程

### 3.1 发布前准备

**Step 1: 更新版本号**

使用 bumpp 工具自动管理版本：

```bash
# 补丁版本（bug fixes）
npm run release:patch
# 或
npx bumpp patch

# 次级版本（新功能）
npm run release:minor
# 或
npx bumpp minor

# 主要版本（破坏性变更）
npm run release:major
# 或
npx bumpp major
```

**版本选择指南**:

| 变更类型  | 命令                    | 版本变化      | 示例场景            |
| --------- | ----------------------- | ------------- | ------------------- |
| **Patch** | `npm run release:patch` | 0.4.0 → 0.4.1 | 修复 typo、性能优化 |
| **Minor** | `npm run release:minor` | 0.4.1 → 0.5.0 | 新增图标、新功能    |
| **Major** | `npm run release:major` | 0.5.0 → 1.0.0 | API 变更、删除图标  |

**Step 2: 查看变更日志**

```bash
git log --oneline --decorate
```

**输出示例**:


**Step 3: 确认 package.json**

## 🔁 四、CI/CD自动化

### 4.1 GitHub Actions 配置

**工作流文件**: `.github/workflows/release.yml`

```yaml
name: Release

on:
  push:
    branches:
      - main

jobs:
  release:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          registry-url: "https://registry.npmjs.org"

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npm run typecheck

      - name: Run tests
        run: npm run test

      - name: Build
        run: npm run build

      - name: Release
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
        run: |
          git config --global user.name 'GitHub Actions Bot'
          git config --global user.email 'actions@github.com'
          npm run release
```

### 4.2 环境变量配置

**添加 NPM Token**:

1. 获取 NPM Token:

   ```bash
   npm token create
   ```

2. 在 GitHub 仓库设置中添加 Secret:
   - Settings → Secrets and variables → Actions
   - New repository secret
   - Name: `NPM_TOKEN`
   - Value: `npm_xxxxxxxxxxxxx`

**撤销已发布的版本**:

```bash
# 废弃某个版本（不推荐删除）
npm deprecate @type-dom/svgs@0.4.1 "Critical bug, please upgrade to 0.4.2"

# 如果必须取消发布（24 小时内）
npm unpublish @type-dom/svgs@0.4.1
```

**注意事项**:

- ⚠️ NPM 政策：发布 24 小时后不能取消发布
- ⚠️ 如果有其他包依赖该版本，不能取消发布
- ✅ 推荐使用 deprecate 标记有问题版本

## 📚 六、最佳实践总结

### 6.1 发布检查清单

**每次发布前必查**:

- [ ] 所有测试通过 (`npm run test`)

### 6.2 版本管理建议

**推荐策略**:

```
开发阶段：0.x.y (快速迭代)
稳定版本：1.x.y (向后兼容)
长期支持：LTS 版本
```

**发布频率**:

- 🟢 Patch: 按需（bug 修复立即发布）
- 🟡 Minor: 每 2-4 周（累积新功能）
