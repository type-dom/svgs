## 📋 使用说明

本清单用于指导 @type-dom/svgs 项目的代码审查工作，确保代码质量和一致性。

### 审查流程

```
提交代码 → 自动检查 (CI) → 同行审查 → 问题修复 → 合并
    ↓           ↓             ↓          ↓        ↓
  预检查     类型检查       详细审查    复审     最终合并
           单元测试       功能验证
           构建验证       性能评估
```

## ✅ 一、TypeScript 类型检查

### 1.1 类型定义

- [ ] **严格模式启用**
  ```json
  {
    "compilerOptions": {
      "strict": true,
      "noImplicitAny": true,
      "strictNullChecks": true
    }
  }
  ```

- [ ] **显式类型标注**
  ```typescript
  // ✅ 正确：显式类型
  export class TdAddSvg extends TypeSvgSvg {
    className: 'TdAddSvg';
    override childNodes: SvgPath[];
    
    constructor(params: SvgProps = {}) {
      super(params);
    }
  }
  
  // ❌ 错误：隐式 any
  export class TdAddSvg {
    className = 'TdAddSvg';
    childNodes = [];
  }
  ```

- [ ] **接口实现完整**
  ```typescript
  // ✅ 正确：实现所有必需属性
  interface SvgComponent {
    className: string;
    childNodes: SvgPath[];
    resetSize(w: number, h: number): void;
  }
  
  export class TdAddSvg implements SvgComponent {
    className: 'TdAddSvg';
    childNodes: SvgPath[];
    resetSize(w: number, h: number) { /* ... */ }
  }
  ```

### 1.2 类型安全

- [ ] **无类型断言滥用**
  ```typescript
  // ❌ 避免：不必要的断言
  const path = svg.childNodes[0] as any;
  
  // ✅ 推荐：使用正确类型
  const path = svg.childNodes[0] as SvgPath;
  
  // ✅ 更好：类型守卫
  function isSvgPath(node: any): node is SvgPath {
    return node instanceof SvgPath;
  }
  ```

- [ ] **泛型使用正确**
  ```typescript
  // ✅ 正确：泛型约束
  function createSvg<T extends TypeSvgSvg>(
    SvgClass: new () => T,
    props: SvgProps
  ): T {
    return new SvgClass();
  }
  ```

## 🏗️ 二、架构设计审查

### 2.1 继承关系

- [ ] **正确的继承链**
  ```typescript
  // ✅ 正确：单继承
  export class TdAddSvg extends TypeSvgSvg {
    // ...
  }
  
  // ❌ 错误：多重继承尝试
  export class TdAddSvg extends TypeSvgSvg implements OtherInterface {
    // 可以实现接口，但不能继承多个类
  }
  ```

- [ ] **override 关键字使用**
  ```typescript
  // ✅ 正确：标注 override
  export class TdAddSvg extends TypeSvgSvg {
    override childNodes: SvgPath[];
    override resetSize(w: number, h: number): void {
      super.resetSize(w, h);
      // custom logic
    }
  }
  ```

### 2.2 职责分离

- [ ] **单一职责原则**
  ```typescript
  // ✅ 正确：专注于 SVG 定义
  export class TdAddSvg extends TypeSvgSvg {
    constructor(params: SvgProps = {}) {
      super(params);
      this.className = 'TdAddSvg';
      addAttrObj(this, { viewBox: '0 0 1024 1024' });
      this.resetSize(24, 24);
      this.childNodes = [/* paths */];
    }
  }
  
  // ❌ 避免：混合业务逻辑
  export class TdAddSvg extends TypeSvgSvg {
    constructor(params: SvgProps = {}) {
      super(params);
      // 不应该在构造函数中调用 API 或处理业务
      fetch('/api/data').then(/* ... */);
    }
  }
  ```

## 📝 三、命名规范审查

### 3.1 组件命名

- [ ] **遵循命名模式**: `{Prefix}{IconName}{Style}Svg`
  ```typescript
  // ✅ 正确的命名
  TdAddSvg              // Common
  ElArrowDownSvg        // Element Plus
  FlAccessTimeFilledSvg // FluentUI
  
  // ❌ 错误的命名
  AddSvgComponent       // 缺少前缀
  tdAddSvg              // 首字母应大写
  ADD_SVG               // 不应全大写
  ```

### 3.2 文件命名

- [ ] **文件名与类名一致**
  ```
  ✅ TdAddSvg.ts         # 类名：TdAddSvg
  ✅ ElArrowDownSvg.ts   # 类名：ElArrowDownSvg
  
  ❌ add-svg.ts          # 不匹配
  ❌ Td_Add_Svg.ts       # 不使用下划线
  ```

### 3.3 变量命名

- [ ] **camelCase 用于变量和函数**
  ```typescript
  // ✅ 正确
  const svgInstance = new TdAddSvg();
  function createSvgElement() { /* ... */ }
  
  // ❌ 错误
  const SVG_Instance = new TdAddSvg();
  function CreateSvgElement() { /* ... */ }
  ```

- [ ] **PascalCase 用于类和类型**
  ```typescript
  // ✅ 正确
  class TdAddSvg { }
  interface SvgProps { }
  type PathData = string;
  
  // ❌ 错误
  class tdAddSvg { }
  interface svgProps { }
  ```

## 🔧 四、代码质量审查

### 4.1 构造函数规范

- [ ] **必须调用 super()**
  ```typescript
  // ✅ 正确
  constructor(params: SvgProps = {}) {
    super(params);
    // ... initialization
  }
  
  // ❌ 错误
  constructor(params: SvgProps = {}) {
    // 忘记调用 super(params)
    this.className = 'TdAddSvg';
  }
  ```

- [ ] **初始化顺序合理**
  ```typescript
  // ✅ 推荐的初始化顺序
  constructor(params: SvgProps = {}) {
    super(params);                          // 1. 父类初始化
    this.className = 'TdAddSvg';           // 2. 设置类名
    addAttrObj(this, { name: 'TdAddSvg' }); // 3. 添加属性
    addAttrObj(this, { viewBox: '0 0 1024 1024' });
    this.resetSize(24, 24);                // 4. 设置尺寸
    this.childNodes = [                    // 5. 创建子节点
      new SvgPath({ d: '...', fill: '#C9C9C9' })
    ];
  }
  ```

### 4.2 路径数据验证

- [ ] **path data 格式正确**
  ```typescript
  // ✅ 正确：有效的路径命令
  new SvgPath({
    d: 'M512 64C264.6 64 64 264.6 64 512s200.6 448 448 448 448-200.6 448-448S759.4 64 512 64z',
    fill: '#C9C9C9'
  });
  
  // ❌ 错误：无效的路径
  new SvgPath({
    d: 'invalid path data',
    fill: '#C9C9C9'
  });
  ```

- [ ] **viewBox 标准化**
  ```typescript
  // ✅ 正确：统一使用 0 0 1024 1024
  addAttrObj(this, { viewBox: '0 0 1024 1024' });
  
  // ❌ 避免：不一致的 viewBox
  addAttrObj(this, { viewBox: '0 0 24 24' });
  ```

### 4.3 默认尺寸

- [ ] **统一的默认尺寸**
  ```typescript
  // ✅ 正确：默认 24x24
  this.resetSize(24, 24);
  
  // ❌ 避免：不一致的尺寸
  this.resetSize(32, 32);  // 除非有特殊理由
  ```

## 💾 五、数据结构审查

### 5.1 childNodes 管理

- [ ] **类型一致性**
  ```typescript
  // ✅ 正确：明确的类型
  override childNodes: SvgPath[] = [
    new SvgPath({ d: '...', fill: '#C9C9C9' }),
    new SvgPath({ d: '...', fill: '#FFFFFF' })
  ];
  
  // ❌ 错误：混合类型
  override childNodes: any[] = [
    new SvgPath({ d: '...' }),
    { d: '...' }  // 不是 SvgPath 实例
  ];
  ```

- [ ] **必填字段检查**
  ```typescript
  // ✅ 正确：包含必需的 path 属性
  new SvgPath({
    d: 'M512 64...',
    fill: '#C9C9C9'
  });
  
  // ❌ 错误：缺少必需字段
  new SvgPath({
    fill: '#C9C9C9'
    // 缺少 d 属性
  });
  ```

### 5.2 属性对象

- [ ] **attrObj 使用规范**
  ```typescript
  // ✅ 正确：使用 addAttrObj
  addAttrObj(this, {
    viewBox: '0 0 1024 1024',
    name: 'TdAddSvg'
  });
  
  // ⚠️ 注意：避免直接修改
  this.attrObj.viewBox = '0 0 1024 1024';
  ```

## 🔍 八、性能优化审查

### 8.1 内存管理

- [ ] **避免内存泄漏**
  ```typescript
  // ✅ 正确：适当的清理
  unmount() {
    this.childNodes.forEach(path => path.destroy());
    super.unmount();
  }
  
  // ❌ 错误：未清理引用
  unmount() {
    // 忘记清理子节点
    super.unmount();
  }
  ```

### 8.2 渲染优化

- [ ] **最小化 DOM 操作**
  ```typescript
  // ✅ 推荐：批量更新
  updatePaths(newPaths: SvgPath[]) {
    this.childNodes = newPaths;  // 一次性替换
  }
  
  // ❌ 避免：频繁操作
  updatePaths(newPaths: SvgPath[]) {
    this.childNodes.forEach(p => this.removeChild(p));
    newPaths.forEach(p => this.addChild(p));
  }
  ```

## 📊 审查评分标准

### 评分等级

| 等级 | 分数 | 标准 | 处理方式 |
|-----|------|------|---------|
| **优秀** | 90-100 | 完全符合规范，代码质量高 | 直接合并 |
| **良好** | 80-89 | 基本符合规范，有小问题 | 修复后合并 |
| **合格** | 70-79 | 满足基本要求，需改进 | 必须修复问题 |
| **不合格** | <70 | 多处不符合规范 | 重新编写 |

### 关键否决项

以下问题直接判定为不合格：
- ❌ TypeScript 类型错误
- ❌ 单元测试失败
- ❌ 构建失败
- ❌ 违反核心架构原则
- ❌ 缺少必要的测试
